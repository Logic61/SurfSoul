# QQ 二代可选 OpenAI API

默认不会启用，不影响 DeepSeek 或 Codex CLI，伴学和其他 DSH 会话不变。仅在 SurfCore → 模型 → QQ 对话模型选「OpenAI API（单独计费）」并保存时启用。默认 GPT-6.2 Sol / low；目录由同一项目密钥调用官方只读 `/v1/models` 得到；只把已知支持 QQ 结构化输出与图文的候选加入选择器，例如可见的 `gpt-4o`（旧版）、`chat-latest`、GPT-4.1 和 GPT-6.2 Sol/Astra。其余可见 ID 单独列出，目录不可用也不清空已选模型。GPT-4o / Chat Latest 等不支持思考档位的模型，既不向 API 传 reasoning，也不向 DSH 注册空思考档位或承接上一模型的档位；上下文缩短时仍走正常压缩。不使用 ChatGPT/Codex 登录。优先读取 DSH 启动环境的项目密钥，Windows 上未继承时读取当前账户用户环境变量 `OPENAI_API_KEY`（请勿贴到聊天、Shell 历史或插件配置）；完全退出再重新启动 DSH（仅隐藏窗口不一定重载）。若经代理访问，请让 DSH 进程继承 `HTTPS_PROXY` 和 `NODE_USE_ENV_PROXY=1`，并用支持该标志的 Node；只有系统回环代理而未配置到 Node 时适配器会报错，不会擅自绕过。重新切回 Codex CLI 或 DeepSeek 即回滚。

启用后，角色提示及 QQ 模型可见历史和图片发送至官方 Responses API。明确使用 `store:false`，不表示服务端任何数据都不留存。API 用量依所选 OpenAI API 项目计费；此处不承诺特定账户有额度。请求没有可执行的 API 工具：模型的结构化提议仍交给原有 DSH 的动作校验、执行和 QQ 发送闸门。错误不会静默回退到其他引擎。不启用用户配置时，不发送请求。

## ModelsNexus 的 Claude 和 Gemini

在「SurfCore → 模型 → QQ 对话模型」选「ModelsNexus（Claude / Gemini）」，再选择模型并保存。默认不启用，不会改变 DSH 的全局模型。目录在打开模型页时自动读取，也能手动刷新。固定入口是 `https://modelsnexus.org`，以各自密钥调用 `/v1/models`，仅列出该密钥能看到的同系列对话模型。Claude 用 `CLAUDE_KEY`，Gemini 用 `GEMINI_ROUTER_KEY`。优先读进程环境，Windows 未继承时读用户环境变量，不在模型页填写密钥。一边失败不影响另一边的目录，也不会清掉已选模型或改用另一把密钥。

选中后通过 `/v1/chat/completions` 发送模型可见的 QQ 上下文及图片，使用网关默认的思考行为。动作输出在本机校验，工具和发言仍由 DSH 与桥接执行，桥接会话令牌不会提交给网关。目录不返回实际上下文窗口，轮换及压缩按保守的 128k 上限处理。用量记为 `surfcore-modelsnexus`，未配置价表时显示待定价；如需配置，可在 `pricing.models["surfcore-modelsnexus/<模型 ID>"].off` 记录每百万 token 的价格。首次部署需重载 DSH 与 QQ 桥接以加载新代码，此后切换模型不需重启。要停用，保存原引擎即可。

离线验证运行 `node --test scripts/test-qq-modelsnexus.mjs scripts/test-qq-model-settings.mjs plugins/surfcore/scripts/test-client-contract.mjs`。两把真实密钥的只读目录可在模型页分别核对数量。

## QQ 逐步用量与收尾

### 工具后的缓存与多来源查证

衡量固定前缀时，以相同布局首次写入、后续确实可复用的 token 为分母。看图工具返回后，先前的纯文字来信保留在同一断点前，图片和取图记录一起交给模型。模型在读过新的文字补充后，可以为本次发送预写小记；核验其后的成功送达、水位和补充身份后才结束。更新要求、错误回执或未完成的工作继续由模型处理。

Sol 的普通 QQ 请求把固定指令与背景放在显式缓存断点前，本步允许的动作放在断点后，补载能力时仍执行当步的严格输出校验。单条来信指定一个网址、没有连续查证意图时保留原请求格式。用量同时看总输入、缓存读、缓存写与输出。成功发送或关闭后，若模型已留好小记、原会话水位及回执均核对通过，宿主可直接结束该轮。看图后的这种收尾也能省掉一次图片读取和模型请求。

签名来信明确要求多来源查证、比较或沿引用查找时，Sol 选择的第一项原生网页读取或搜索可以启动一个轻量任务。DeepSeek Flash 收到脱敏的短问题、来源编号和公开网页摘录；工具执行仍走 DSH 当步允许的 `web-search-safe`，最多读取四页。宿主核对引文逐字出自该页，Sol 根据来源完成 QQ 回复。资料不足、工具失败或超时时交还原始记录；Sol 也可以补载网页工具自行复查。单页直查和图片继续由主模型处理。

DSH 启动时读取 `DEEPSEEK_API_KEY`。`SURFCORE_QQ_SOURCE_WORKER=off` 关闭子任务，`SURFCORE_QQ_CACHE_FORMAT=off` 恢复顶层输出格式，`SURFCORE_QQ_FINISH=off` 关闭条件收尾。更改启动环境后需在空闲时重载宿主。子任务逐步用量写入 `state/source-worker-input-metrics.jsonl`，与主模型用量分别统计。运行 `node --test scripts/test-qq-source-worker.mjs scripts/test-qq-openai-api.mjs` 复核。

### QQ 只读工具预加载

QQ 使用 OpenAI API、Codex CLI 或 ModelsNexus 适配器时，默认在本机先检查当前可用的工具目录。明确要求查询 BV 号、指定网页、收藏表情、合并转发或图片时，若对应说明尚未展示，会直接放进本次主模型请求。语义含糊、可能用到其中一项能力时，才向 OpenRouter 的 `typesafe/jev-1.14` 询问一次。闲聊、已展示的能力、后续工具步骤和压缩跳过这一步。原生 DeepSeek 路由使用其原有菜单。

只有桥接签名有效、水位仍匹配、只有一条待处理消息的普通来信可以进入。发送给 OpenRouter 的内容限于当前短句和理解承接所需的一条助手原话，优先取明确的引用；群聊要求 @ 或引用机器人，只有引用能带出上一句。文本先遮盖已知凭据格式、邮箱、常见号码和网址。附件、群号、会话令牌、历史包、工具参数都留在原流程。Jev 返回的选项概率须达到 0.60，且工具名称须在宿主当次提供的只读目录内。主模型决定是否调用、核查结果、撰写并发送回复。

DSH 启动环境使用 `OPENROUTER_API_KEY`。默认 `SURFCORE_QQ_JEV=auto`，`rules` 只用本地规则，`off` 关闭预加载；改环境后重载宿主生效。缺少密钥或 OpenRouter 超过 2.5 秒即走原流程，服务错误后 30 秒内跳过远程查询。宿主的只读 `GET /dsh-surfcore/api/qq-jev-status` 显示模式、模型名及是否读到密钥。辅助调用单独记在 `state/jev-input-metrics.jsonl`，包含决策来源、工具名、服务返回的用量和费用及延迟，主模型的 DSH 账本单独计算。离线运行 `node scripts/test-qq-jev-preload.mjs`。

### 条件收尾

在已验证、完整的普通唤醒中，GPT-6.2 Sol 可在文字发送或自然收尾动作中预写私人小记。有后续任务就留空；只结束本轮时无需关闭对话。适配器核对会话、来信水位、对应的真实工具回执、成功条数和消息编号；需要记录自然结束点时仍调用 DSH 原有收尾工具。退回会恢复原有重试流程，当前回合剩余步骤都由模型继续判断。设置 `SURFCORE_QQ_FINISH=off` 后重载 DSH 即可关闭该优化。

GPT-6.2 Sol / Astra 的普通投影会把受信系统指令放在 developer 开头，把角色资料、来信和工具说明留在 user 层，为可复用前缀设置显式缓存边界。动态执行结果随本次调用传入。图片随原记录和当轮附件一同提交。可独立设置 `SURFCORE_QQ_CACHE_PREFIX=off` 并重载。诊断应同时看总输入、缓存读、缓存写、输出和完整回合调用数。

## 给 GPT-4o 换会话

QQ 二代的配置值 `rotateAfterContextTokens` 是上限。已知模型窗口时实际阈值取该配置与 `floor((窗口−4096)×0.8)` 的较小值；GPT-4o 为 99,123 token，Sol/Astra 在原 220k 配置下仍是 220k，0 关闭。轮换只认会话实际用量或 DSH 上下文投影，不拿累计用量猜；无法证明旧会话可用时先保留未投递消息。达到阈值且确认无在途回合或 DSH 待处理消息才依既有路径归档；新消息只投到新会话一次。旧历史和 SurfCore 记忆保留。

DSH 压缩请求单独返回非空纯文本摘要，不发 QQ、不提供工具、不替换模型。如果完整摘要输入保守估算可能不适合目标窗口，拒绝该摘要调用，不截断旧历史，不悄悄改用其他模型。上线需要 DSH 重新加载插件和单独运行的 QQ 桥接重新启动源码；未重载前旧会话仍保留。

离线验证（测试完全注入模拟 HTTP，不访问 QQ 或 OpenAI）：

```shell
node scripts/test-qq-openai-api.mjs
node scripts/test-qq-context-4o.mjs
node scripts/test-qq-codex.mjs
npm run test:audit
npm run test:regressions
```

## QQ 输入和用量诊断

私聊、被 @ 和普通群聊的续轮可使用近期 QQ 消息和当前回合的工具结果。主人会话沿用原工具范围。后台任务、压缩任务、缺少来源或授权标记的旧会话走完整输入。旧会话仍支持文本格式，新会话可延续角色、环境、约定和动作更新。在控制台的「群聊与私聊的环境提示」选择有效期，原有未指定有效期的记录只在开场注入。

`state/qq-input-metrics.jsonl` 记录每个模型步骤的渠道、模型、是否裁剪、回退原因、系统提示、工具目录、序列化输入和动作 schema 的字符数，以及图像数量、耗时和模型返回的 usage。序列化输入含工具目录，两项不能直接相加。缺少 usage 的请求单独标明；统计文件只含指标，达到 1 MiB 时保留一个轮转副本。B 站对应文件记录各公开身份块的长度和变更情况。

「用量」按模型渠道区分订阅、已标价 API、待定价与历史估算。按渠道登记价表可使用 `pricing.models["surfcore-openai-api/<模型 ID>"].off`，单位为元／百万 token。待定价请求仍计入 token 额度，金额闸门继续按原有兜底价估算。发送前评审归入原 QQ 回合，控制台预览归入内部用量。仅统计模型返回的用量。

诊断对照可在桥接和宿主的启动环境设置 `SURFCORE_QQ_INPUT_MODE=legacy`，再用相同回合分别运行适配器。逐次比较时应同时查看输出和工具结果。离线模拟不产生模型账单。

当前与历史桥接都可能签发会话令牌。适配器识别两种长度，把凭证替换为仅本次请求有效的句柄；DSH 调工具时在本地还原。附件标识独立传递。

## 压缩后恢复、工具补载与网页回执

新版桥接会给 QQ 对话附加本机校验标记。DSH 压缩过开场时，适配器校验原始唤醒文本、场合、活动会话、当前令牌和背景版本，再交给模型角色、当批来信与本轮动作。旧记录等下一次新版唤醒自然接入。原消息与附件仍由 DSH 保管。

模型首读成功的公开网页、检索及 B 站文本回执时可见全文。后续超过门槛的回执可按编号、字串或字符位置读取原文；发送失败重试会重新附上最近一份来源及失败原因。只有 8,192 至 262,144 个 JS 字符、单一文本块并能关联到实际读取调用的结果会折叠。当前轮使用原始会话消息，已验证会话可在后续回合回查短期快照。缓存按场合、会话代际和当前授权类别隔离，有效期 24 小时，每一代最多保留最近六份；访问时清理旧副本。超过上限的完整回执、错误、图片与其他工具结果继续传递。

宿主当前提供的工具超过 24 项且识别到 QQ 核心动作时，模型先获得常用工具及其他工具的名称，可以补载精确名称的参数说明。每个 DSH 步骤最多额外执行三次本地上下文操作，每次发生的模型调用均写逐步指标，成功回合汇总实际用量。工具的执行权限和发送审查仍由 DSH 与桥接判断。

保留新版会话恢复、仅关闭工具补载及回执折叠时，在 DSH 启动环境设 `SURFCORE_QQ_CONTEXT_ACTIONS=off`。适配器整组回退到本次改动前的路径可设 `SURFCORE_QQ_CONTEXT_VERSION=previous` 并重载宿主。历史诊断用的 `SURFCORE_QQ_INPUT_MODE=legacy` 会进一步关闭此前已有的短输入规划。

2026-11-25 使用 11 个合成 QQ 完整回合做成对实测。按每题的答复内容和动作要求，改动前通过 7 题，改动后通过 11 题。两组模型调用分别为 32 和 22 次，总输入分别为 152,304 和 102,933 token，总输出分别为 2,106 和 1,572 token。10 个成功取图的用例中，取图后第一次模型请求命中上一请求所写前缀的 38,592 / 38,592 token，改动前为 34,340 / 38,592。这个比例只覆盖已预热的指定前缀；冷启动和新增对话内容另计。
